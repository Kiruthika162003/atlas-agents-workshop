1What you will build

Atlas is a map agent. You tell it where you are and what you are after, and it shows you three places worth the walk, with a description you can check and the walking route to each one.

You will not build it in one go. You will ask the same question six times, and each time the agent gets exactly one new thing. That way you can see what each idea is for.

THE QUESTION YOU ASK AT EVERY STEPI'm at Grand Central Market in Los Angeles. Where should I eat?
StepThe one new ideaWhat changes in the answer
1An agent is a model with a jobConfident, and not checked against anything
2A tool is a Python functionReal places with real distances
3MCP serves those tools to any agentSame answer, and the agent has no map code left
4MCP auth decides who may call the toolsWithout a login, the tools are refused
5A2A lets one agent ask anotherEach place gets a description with facts
6A skill is a new job in one fileThe agent can plan a walking tour

At the end, the same pieces run behind a map:

your browser ── web app ── recommendation agent ──MCP──▶ places server
                                   │                       geocode · nearby_places · walking_route
                                   │
                                   ├──A2A──▶ description agent ── Google Search
                                   │
                                   └──skill── walking-tour (one file of instructions)
MCP: an agent calling toolsA2A: an agent asking another agentSkill: instructions loaded on demand

2Before you start

You do not need to have built an agent before, or to have used Google Cloud. This guide starts from an empty laptop.

You will needDetails
A laptopWindows, macOS or Linux, with permission to install programs
A Google accountAny Gmail address works
A bank cardGoogle Cloud asks for one to open a billing account, even for small use
About 45 minutesFor sections 3 to 5, which you only ever do once
About an hourFor the steps themselves
What it costs. Each question you ask an agent is a handful of model calls, and in the later steps three Google Search lookups as well. Following this whole guide once is small change, but it is not free. Section 13 ends with how to stop everything.

2.1 How to open a terminal

A terminal is a window where you type commands. You will use it throughout.

OnDo this
WindowsPress the Windows key, type PowerShell, press Enter
macOSPress Cmd+Space, type Terminal, press Enter
LinuxPress Ctrl+Alt+T

2.2 How to read the dark boxes

Dark boxes show a terminal. A bright line after the green > is something you type, followed by Enter. Do not type the > itself. Grey lines are what the computer answers; yours may differ slightly.

python --version
Python 3.13.0

Type one line at a time and wait for it to finish before typing the next.

3Install three programs

Python runs the code. Git downloads it. The Google Cloud CLI signs you in. If you already have one of them, run its check and skip ahead.

3.1 Python

  1. Go to python.org/downloads and press the yellow Download Python button.
  2. Open the file that downloads.
  3. Windows only: on the first screen, tick Add python.exe to PATH at the bottom. Then press Install Now.
  4. macOS: press Continue through the installer and accept the defaults.
  5. Close your terminal and open a new one. A terminal only notices new programs when it starts.

Check it:

python --version
Python 3.13.0

Any version from 3.11 up is fine. On macOS and Linux the command may be python3. If python is not found, try python3 --version, and use python3 wherever this guide says python until section 5.2.

Windows says "Python was not found" and opens the Store? The PATH box was not ticked. Run the installer again, choose Modify, and tick it.

3.2 Git

  1. Windows: go to git-scm.com/downloads, download the Windows installer, open it, and press Next on every screen. The defaults are fine.
  2. macOS: type git --version in the terminal. If Git is missing, a window offers to install the developer tools. Press Install.
  3. Close your terminal and open a new one.

Check it:

git --version
git version 2.54.0.windows.1

3.3 The Google Cloud CLI

This gives you the gcloud command. It is how your laptop proves to Google who you are, so that the code never needs a secret key.

  1. Go to cloud.google.com/sdk/docs/install and choose your operating system.
  2. Windows: download GoogleCloudSDKInstaller.exe, open it, and accept the defaults. On the last screen you can untick the boxes that offer to start a shell; you will sign in from your own terminal in section 4.
  3. macOS and Linux: follow the steps on that page for your system. They end with running an install script that adds gcloud to your terminal.
  4. Close your terminal and open a new one.

Check it:

gcloud --version
Google Cloud SDK 571.0.0

Your number will be different. If the terminal says gcloud is not recognised, close every terminal window and open a fresh one. If it still fails, run the installer once more.

4Set up Google Cloud

The agents use Google's Gemini model. Google runs it for you, and to use it you need four things: a project, a billing account, the service switched on, and your laptop signed in.

4.1 Create a project

A project is a labelled box that holds everything you use on Google Cloud and the bill for it.

  1. Open console.cloud.google.com/projectcreate and sign in with your Google account. The first time, accept the terms of service.
  2. Type a project name, for example my-atlas.
  3. Under the name box there is a line that begins Project ID. Write it down. It looks like my-atlas-123456, and you will type it twice later. The ID is what matters, not the name.
  4. Press Create and wait for the bell at the top right to show it is done.

4.2 Open a billing account and connect it

  1. Open console.cloud.google.com/billing.
  2. If you have no billing account, press Create account (it may say Add billing account). Choose your country, enter your card, and confirm. New accounts are often offered free trial credit on this screen; accept it if you see it.
  3. Now connect it to your project. On the same Billing page, open the My projects tab, find your project, press the three dots at the end of its row, choose Change billing, and pick your billing account.

You know it worked when your project's row shows the billing account's name instead of Billing is disabled.

4.3 Sign in from your terminal

Type these two lines. Replace YOUR_PROJECT_ID with the ID you wrote down.

gcloud auth login
gcloud config set project YOUR_PROJECT_ID
Line 1
Opens your browser. Choose your Google account and press Allow. The terminal then says you are logged in.
Line 2
Tells gcloud which project to work in. It answers with a line that starts Updated property.

4.4 Switch on Gemini

On Google Cloud, Gemini is reached through a service called Vertex AI. Every service is off until you switch it on for your project. One line does it:

gcloud services enable aiplatform.googleapis.com

It thinks for up to a minute and then reports that the operation finished. If it complains about billing, go back to 4.2: the project is not connected to a billing account yet.

4.5 Sign in the programs on your laptop

gcloud auth application-default login

The browser opens again. Choose the same account and press Allow.

This looks like a repeat of 4.3, but it is a different login. The first one signed you in to the gcloud tool. This one signs in programs running on your laptop, which is what the agents are. It is the reason there is no API key anywhere in the code.

7Step 1: an agent with nothing but confidence

In the dropdown, pick agent_1_simple. Type the question and press Enter.

ASKI'm at Grand Central Market in Los Angeles. Where should I eat?
You will see
A fluent answer in a second or two, with no tool calls on the screen.
It means
The model is recalling, not looking. A stall that closed last year sounds exactly as confident as one that is open.
Behind it
The whole agent is a name, a model and an instruction. Open learn/agent_1_simple/agent.py; it is about twenty lines.
root_agent = Agent(
    name="agent_1_simple",
    model=os.getenv("ATLAS_MODEL", "gemini-3.8-flash"),
    description="A local guide with no tools.",
    instruction=("You are Atlas, a local guide. ... You have NO tools and NO map ..."),
)

Pick agent_2_tools and ask the same question.

You will see
Real places with real distances: a bakery 13 metres away, a pasta restaurant at 81 metres.

9Step 3: MCP

The three functions work, but they live inside one agent's file. The next agent would have to copy them. MCP, the Model Context Protocol, is an agreed way to serve tools so that any agent can use them.

Open a second terminal, switch on the virtual environment, and start the places server. Leave it running.

python mcp_server/server.py
Open. Anyone who can reach this address may call the tools.
INFO:     Uvicorn running on http://localhost:8001 (Press CTRL+C to quit)

Back in the browser, pick agent_3_mcp and ask the same question.

You will see
The same answer as step 2, and new lines appearing in the server's terminal each time a tool is called.
It means
The tools moved out of the agent. Write them once, and any program that speaks MCP can use them.
Behind it
In mcp_server/server.py the functions are the same, with @mcp.tool() on top. In learn/agent_3_mcp/agent.py there is no map code left: the agent points at an address and asks the server what it offers.
places = McpToolset(
    connection_params=StreamableHTTPConnectionParams(url="http://localhost:8001/mcp", timeout=60),
)

root_agent = Agent(..., tools=[places])

Look again at what the server printed when it started: Anyone who can reach this address may call the tools. On your laptop that is only you. On the internet it is everybody.

10.3 Let the agent in

In the browser, pick agent_4_mcp_auth and ask the same question. It works, because this agent shows your Google login to the server.

It means
The lock is in the server's code, not in a polite instruction to a model. A request with no valid login never reaches a tool.
Behind it
MCP auth is built on OAuth, the same family of standards behind "Sign in with Google". Three parties are involved. Google issues a signed token that says who you are. The agent carries that token with every request. The server checks Google's signature, checks the expiry, and checks that the account is on its list. The server never sees a password.
class GoogleSignIn:
    """Lets a caller in only if Google vouches for them and they are on the list."""

    async def verify_token(self, token: str) -> AccessToken | None:
        try:
            who = id_token.verify_oauth2_token(token, google_transport.Request())
        except ValueError:
            return None                       # forged or expired
        if who.get("email") not in ALLOWED:
            return None                       # a real account, but not invited
        return AccessToken(token=token, client_id=who["email"], scopes=[], expires_at=who["exp"])
Before you go on, unlock the server. The next steps use agents that send no login. Go to the server's terminal, press Ctrl+C, and start it the plain way: python mcp_server/server.py. You can close the third terminal.
About agent_5_remote_mcp. You will see it in the dropdown. It is the same agent pointed at a places server running in the cloud, and it is shown live in the session. It needs a deployed server, so this guide skips it.

11Step 5: A2A

Finding places and describing them well are different jobs. Describing needs a web search and a strict rule about not inventing things. So that becomes a second agent, running as its own program.

In the third terminal (or a new one, with the virtual environment on), start the description agent and leave it running:

python description_agent/agent.py
INFO:     Uvicorn running on http://localhost:8002 (Press CTRL+C to quit)

Every A2A agent publishes a card that says who it is and what it does. Open http://localhost:8002/.well-known/agent-card.json in your browser to read it:

{
  "name": "description_agent",
  "description": "Describes one real place in a few checked sentences.",
  "supportedInterfaces": [
    { "url": "http://localhost:8002", "protocolBinding": "JSONRPC", "protocolVersion": "1.0" }
  ],
  "capabilities": { "streaming": true }
}

Now pick agent_6_a2a in the lessons and ask the same question.

You will see
Descriptions with facts in them: who founded the bakery, what the trattoria is known for, that one place takes no walk-ins.
It means
MCP gives an agent hands. A2A gives it colleagues. The first agent does not know how the second one works, only what its card promises.
Behind it
The description agent searches Google for each place and is told to write only what the search confirms. In learn/agent_6_a2a/agent.py, two lines connect them:
description_agent = RemoteA2aAgent(
    name="description_agent",
    description="Describes one real place in a few checked sentences. Send one place per request.",
    agent_card="http://localhost:8002" + AGENT_CARD_WELL_KNOWN_PATH,
)

root_agent = Agent(..., tools=[places, AgentTool(description_agent)])

12Step 6: skills

Suppose you want the agent to plan walking tours. You could make its instruction longer, and longer again for the next idea. A skill is the alternative: a folder with one file of instructions that the agent only reads when a request needs it.

Pick agent_7_skills and ask for a tour:

ASKI'm at Grand Central Market in Los Angeles. Plan me a walking tour of fun things.
You will see
Calls named list_skills and load_skill, then the usual map tools, then a tour with times.
It means
The agent learned a new job from a text file. Ask it the eating question instead and it never opens that file.
Behind it
Open skills/walking-tour/SKILL.md. The two lines at the top are all the agent sees until it decides it needs the rest.
---
name: walking-tour
description: Turn a few nearby places into a walking tour with an order, timings
  and a total. Use when someone asks for a tour, an itinerary, ...
---

# Planning a walking tour

Work only from what the tools returned. Never add a place, a time or a fact of your own.
...

Try changing a number in that file, for example the minutes to allow at a museum. Stop adk web learn with Ctrl+C, start it again, and ask once more. You changed what the agent does without touching any Python.

15No Google Cloud? Run it on your own laptop with Gemma

Gemma is Google's open model. With a recent graphics card you can run it yourself, and then nothing in this guide needs a cloud project or costs anything.

  1. Install Ollama from ollama.com.
  2. Download the model. It is about 6 GB.
  3. Build the copy this project uses, which has more room to read tool results.
ollama pull gemma4:e4b-it-qat
ollama create atlas-gemma -f Modelfile

Then start the app and type gemma when it asks:

python start.py
Model: gemini (Google Cloud) or gemma (this laptop)? [gemini] gemma

For the lessons, change the last line of .env to ATLAS_MODEL=ollama_chat/atlas-gemma before you run adk web learn.

What is different on Gemma. It is slower, about a minute for a question on a laptop graphics card. And it has no Google Search, so the description agent reads Wikipedia instead. Famous places get real history; a small cafe gets an honest "little is published about it".

17Small glossary

WordIn plain words
AgentA model in a loop that decides its own next step: think, use a tool, read the result, repeat
ToolA function the agent can ask your program to run
MCPModel Context Protocol. A shared way to serve tools so any agent can use them
MCP serverThe program that offers the tools. Here, the places server
OAuthThe standard behind "Sign in with Google". Someone you trust issues a token that proves who the caller is
TokenA short-lived, signed proof of identity. Here it lasts an hour
401The web's code for "I do not know who you are". What the locked server answers to a stranger
A2AAgent to Agent. A shared way for one agent to hand a task to another
Agent cardA small public file where an A2A agent says who it is and what it does
SkillA folder with a SKILL.md file: instructions the agent loads only when it needs them
GroundingMaking the model answer from a search or a document, not from memory
Virtual environmentA private set of Python packages for one project
PortA numbered door on your computer. Each program in this guide listens on its own
localhostYour own computer, as seen from itself
